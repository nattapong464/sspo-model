# สำรองข้อมูล SSPO ไป Google Drive อัตโนมัติ และส่งอีเมลแจ้งเตือน

สคริปต์ชุดนี้จะดึงข้อมูลทั้งหมดจาก Firebase ไปเก็บไว้ในโฟลเดอร์ **"SSPO Backups"** บน Google Drive ของคุณ**ทุกวันประมาณตี 2** ใน 1 วันจะได้ 2 ไฟล์

- **Google Sheet**: แยกเป็นแท็บ Patients / Requests / Users / Notifications เปิดอ่านหรือค้นหาได้ทันที
- **ไฟล์ JSON**: สำเนาข้อมูลครบทุกฟิลด์ เก็บไว้กู้คืนข้อมูลถ้าจำเป็น

ไฟล์ที่เก่ากว่า 30 วันจะถูกย้ายไปถังขยะของ Drive เอง (ปรับจำนวนวันได้ที่ `KEEP_DAYS`)

> ⚠️ ต้องทำทุกขั้นตอนด้วย **บัญชี Google ที่เป็นเจ้าของโปรเจกต์ Firebase "sspo-model"**
> เพราะสคริปต์อ่านข้อมูลด้วยสิทธิ์ของบัญชีนั้น จึงไม่ต้องเก็บรหัสผ่านหรือกุญแจใด ๆ ไว้ในสคริปต์

## ติดตั้ง (ประมาณ 10 นาที ทำครั้งเดียว)

1. ไปที่ **https://script.google.com** แล้วกด **New project (โปรเจกต์ใหม่)**
   ตั้งชื่อด้านบนว่า `SSPO Backup`
2. ลบโค้ดเดิมในไฟล์ `Code.gs` ทิ้ง แล้ว**วางเนื้อหาไฟล์ `Code.gs`** จากโฟลเดอร์นี้ลงไปแทน
3. กดไอคอน ⚙️ **Project Settings (การตั้งค่าโปรเจกต์)** แล้วติ๊ก
   **"Show 'appsscript.json' manifest file in editor"**
4. กลับไปหน้า **Editor (ตัวแก้ไข)** แล้วเปิดไฟล์ `appsscript.json`
   ลบของเดิมทิ้ง แล้ว**วางเนื้อหาไฟล์ `appsscript.json`** จากโฟลเดอร์นี้ลงไปแทน จากนั้นกด 💾 Save
5. ที่แถบด้านบน เลือกฟังก์ชัน **`setup`** แล้วกด **▶ Run**
6. Google จะขอสิทธิ์ ให้กด **Review permissions** แล้วเลือกบัญชีของคุณ
   - ถ้าขึ้นว่า *"Google hasn't verified this app"* ให้กด **Advanced → Go to SSPO Backup (unsafe)**
     ขึ้นแบบนี้เพราะเป็นสคริปต์ที่คุณเขียนเองและใช้คนเดียว ไม่ได้มีคนอื่นมาเข้าถึง
   - กด **Allow**
7. รอให้รันเสร็จ ช่อง Execution log จะขึ้นว่า `Backup done: ... -> folder "SSPO Backups"`
   เปิด Google Drive ดู จะเจอโฟลเดอร์ **SSPO Backups** และไฟล์สำรองชุดแรก

เท่านี้ระบบก็จะสำรองข้อมูลให้ทุกวันเอง ดูตารางเวลาได้ที่เมนู ⏰ **Triggers** ทางซ้าย

## ใช้งาน

| ต้องการ | ทำอย่างไร |
|---|---|
| สำรองทันที (เช่น ก่อนนำเข้า Excel ชุดใหญ่) | เปิดสคริปต์ เลือก `backupNow` แล้วกด ▶ Run |
| เปลี่ยนเวลาสำรอง | แก้ `BACKUP_HOUR` แล้วรัน `setup` อีกครั้ง |
| เก็บไฟล์นานขึ้น หรือน้อยลง | แก้ `KEEP_DAYS` |
| หยุดสำรองอัตโนมัติ | เมนู ⏰ Triggers แล้วลบ trigger ของ `backupNow` |
| ถ้าการสำรองล้มเหลว | Google จะส่งอีเมลแจ้งไปที่บัญชีเจ้าของสคริปต์ |

## แก้ปัญหา

- **`Could not read "patients" (403)`**: บัญชีที่รันสคริปต์ไม่มีสิทธิ์ในโปรเจกต์ Firebase
  ให้เปิดสคริปต์ด้วยบัญชีเจ้าของโปรเจกต์ หรือให้เจ้าของไปเพิ่มบัญชีนี้ใน Firebase Console → ⚙️ Project settings → **Users and permissions** เป็น Owner หรือ Editor
- **`(403) ... API has not been used` หรือ `SERVICE_DISABLED`**: เปิดลิงก์ที่อยู่ในข้อความ error แล้วกด **Enable** เปิด Cloud Firestore API จากนั้นรอสัก 2–3 นาทีแล้วรันใหม่

## หมายเหตุเรื่องข้อมูลส่วนบุคคล
ไฟล์สำรองมีชื่อ เบอร์โทร และข้อมูลสุขภาพของผู้ป่วย **อย่าแชร์โฟลเดอร์ SSPO Backups ให้คนอื่น** นอกจากผู้ที่ได้รับอนุญาต

# ส่งอีเมลแจ้งเตือนอัตโนมัติ (Mail.gs)

ไฟล์ `Mail.gs` ส่งอีเมลจาก Gmail ของบัญชีเจ้าของโปรเจกต์ Firebase ประมาณทุก 1 นาที

| เมื่อเกิดเหตุการณ์ | ส่งถึง | ในอีเมลมี |
|---|---|---|
| มีคำขอใหม่ | Admin ทุกคนที่ active | วิชา วัน เวลา สถานที่ ผู้ขอและเบอร์ติดต่อ วัตถุประสงค์ รายชื่อครูต้นแบบพร้อมเบอร์โทร ปุ่มเปิด Admin Dashboard |
| User ยกเลิกคำขอ | Admin ทุกคน | รายละเอียดคำขอ และเหตุผล |
| Admin อนุมัติ / ไม่อนุมัติ / ยกเลิก / ปิดงาน / Reopen | ผู้ขอ | สถานะใหม่ ข้อความจาก Admin และรายชื่อครูต้นแบบ (เบอร์โทรแนบเฉพาะเมื่ออนุมัติแล้ว) |
| Admin แก้รายละเอียดคำขอ | ผู้ขอ | รายละเอียดใหม่ และหัวข้อที่เปลี่ยน |
| มีคนสมัครบัญชีใหม่ | Admin ทุกคน | ชื่อ อีเมล หน่วยงาน |
| Admin อนุมัติบัญชี | เจ้าของบัญชี | แจ้งว่าเริ่มใช้งานได้ |

**หลักการ:** เว็บแอปเขียนแค่ “ขอส่งอีเมลเรื่องอะไร ถึงใคร” ลงใน collection `mail` สคริปต์นี้จะอ่านข้อมูลจริงจากฐานข้อมูลแล้วสร้างอีเมลเอง จึงไม่มีใครแก้เนื้อหาอีเมลจากหน้าเว็บได้ และไม่ต้องเก็บรหัสผ่านอีเมลไว้ที่ไหน

## ติดตั้ง (ทำครั้งเดียว ใช้โปรเจกต์ Apps Script เดียวกับระบบสำรองข้อมูล)

1. **Firestore Rules:** เปิด Firebase Console → Firestore Database → Rules วางเนื้อหาไฟล์ `firestore.rules` ล่าสุด (มีส่วน `mail` เพิ่มเข้ามา) แล้วกด **Publish**
2. เปิดโปรเจกต์ Apps Script `SSPO Backup` (ถ้ายังไม่มี ให้สร้างตามขั้นตอนด้านบนก่อน)
3. กด **+** ข้างคำว่า Files → **Script** ตั้งชื่อ `Mail` แล้ววางเนื้อหาไฟล์ `Mail.gs`
4. เปิด `appsscript.json` วางเนื้อหาไฟล์ `appsscript.json` ล่าสุดแทนของเดิม (มีสิทธิ์ส่งอีเมลเพิ่ม) แล้วกด 💾 Save
5. เลือกฟังก์ชัน **`testMail`** แล้วกด ▶ Run → อนุญาตสิทธิ์ (มีสิทธิ์ส่งอีเมลเพิ่ม) → ตรวจกล่องจดหมายว่าได้อีเมล “SSPO email test”
6. เลือกฟังก์ชัน **`setupMail`** แล้วกด ▶ Run ระบบจะตรวจคิวอีเมลทุก 1 นาทีเอง

## ตรวจสอบและแก้ปัญหา

- ดูอีเมลที่ส่งแล้วหรือไม่สำเร็จได้ที่ Firestore → collection `mail` ช่อง `status` = `sent` / `failed` (ช่อง `error` บอกสาเหตุ)
- `No email address for ...` = บัญชีปลายทางไม่มีอีเมลในโปรไฟล์
- Gmail ฟรีส่งได้ประมาณ 100 ผู้รับต่อวัน (Google Workspace ประมาณ 1,500) ถ้าเกิน อีเมลจะรอส่งในวันถัดไป
- หยุดส่งอีเมล: เมนู ⏰ Triggers แล้วลบ trigger ของ `sendQueuedMail`
- อีเมลมีเบอร์โทรของครูต้นแบบ ไม่ควรส่งต่อนอกทีมผู้สอน
